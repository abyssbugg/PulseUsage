## 3. Triage Classification

### Category A — Immediate Action (Confirmed Low-Risk Fix)

These are confirmed vulnerabilities or bugs with low regression risk, no architectural decision required, and established codebase patterns to follow.

#### A1: CORS Wildcard on Local HTTP API (VULN-002)

- **Classification:** Confirmed defense-in-depth vulnerability
- **CWE:** CWE-942 (Permissive Cross-domain Policy)
- **Location:** `src-tauri/src/local_http_api/server.rs:187-190` (`CORS_HEADERS`)
- **Ground-truth:** `Access-Control-Allow-Origin: *` confirmed. Any website visited by user can `fetch("http://127.0.0.1:6736/v1/usage")` and read provider IDs, plan names, usage metrics.
- **Architectural decision:** None needed. The API is for local apps, not browsers. CORS headers serve no legitimate purpose for this use case.
- **Fix approach:** Remove CORS headers entirely (simplest) OR restrict to `null` origin. Tests at `server.rs:263,319,348` assert `Access-Control-Allow-Origin: *` — must update test expectations.
- **Regression risk:** Low — only affects browser-based access. No internal app consumer uses CORS.
- **PR target:** PR-S1

#### A2: Cache Mutex Poisoned Recovery (BUG-001)

- **Classification:** Confirmed bug (error handling)
- **CWE:** CWE-754 (Improper Check for Unusual Conditions)
- **Location:** `src-tauri/src/local_http_api/server.rs:158` (collection) AND `server.rs:166` (single) — **two occurrences, report cited only one**
- **Ground-truth:** Both use `.expect("cache state poisoned")` which panics if mutex is poisoned (thread panicked while holding lock). This crashes the HTTP server thread.
- **Established pattern:** `ccusage.rs:44,55` uses `.unwrap_or_else(|err| err.into_inner())` — the correct recovery pattern already exists in the codebase.
- **Fix approach:** Replace both `.expect()` calls with `.unwrap_or_else(|err| err.into_inner())` matching the `ccusage.rs` pattern.
- **Regression risk:** Near zero — recovers from poisoned state instead of crashing. No behavior change for the non-poisoned path.
- **PR target:** PR-S2

#### A3: Default Log Level Trace→Info (VULN-005, reclassified)

- **Classification:** Configuration hardening (reclassified from vulnerability)
- **CWE:** CWE-532 (Insertion of Sensitive Information into Log File)
- **Location:** `src-tauri/src/lib.rs:436`
- **Ground-truth:** `.level(log::LevelFilter::Trace)` with comment "Allow all levels; runtime filter via tray menu". This is a documented design decision, not an oversight. The tray menu allows runtime verbosity control.
- **Architectural nuance:** Changing default to `Info` is reasonable ONLY if the tray-menu runtime filter still works. The board's guidance: "Debugging should still be one click away."
- **Fix approach:** Change `.level(Trace)` to `.level(Info)`. Verify tray-menu log-level control still overrides at runtime (it does — `tauri-plugin-log` supports runtime level changes). Add a test or manual verification note.
- **Regression risk:** Low — runtime tray control preserved. Debugging capability unchanged; only the initial default shifts.
- **PR target:** PR-S3

### Category B — Needs ADR Before Implementation

These are architecturally sound recommendations that require a documented decision before implementation because they affect the plugin platform's trust model.

#### B1: Keychain Service-Name Allowlist (VULN-003)

- **Classification:** Defense-in-depth architectural decision
- **CWE:** CWE-732 (Incorrect Permission Assignment for Critical Resource)
- **Location:** `src-tauri/src/plugin_engine/host_api/keychain.rs:84-120` (`readGenericPassword`)
- **Ground-truth:** Any plugin with `keychainRead` capability can read any keychain service the user can access. Service name is plugin-controlled.
- **Current assumption:** Plugins are bundled, trusted, reviewed. No third-party plugins supported.
- **Architectural question:** Is PulseBar a plugin platform (third-party plugins expected) or a curated collection (bundled only)?
- **Why ADR first:** Adding per-plugin service allowlists requires manifest schema changes, migration, compatibility considerations, and ongoing maintenance. If PulseBar remains curated-only, the ROI is low.
- **Decision needed:** ADR-S2 documenting whether to implement now, defer to third-party-plugin era, or reject.
- **PR target:** ADR-S2 (document only, no code)

#### B2: Filesystem Path Confinement (VULN-004)

- **Classification:** Defense-in-depth architectural decision
- **CWE:** CWE-22 (Path Traversal)
- **Location:** `src-tauri/src/plugin_engine/host_api/fs.rs:4-90`, `src-tauri/src/plugin_engine/shared.rs:19-31` (`expand_path`)
- **Ground-truth:** `expand_path` does `~` expansion only. `fs.readText(path)` can read any file the user can access. No confinement to app data directory or provider-specific directories.
- **Current assumption:** Same as B1 — bundled, trusted plugins.
- **Architectural question:** Same as B1 — platform vs curated collection.
- **Why ADR first:** Restricting filesystem access requires per-plugin path allowlists in manifests, which is a schema change. Provider plugins legitimately need to read from provider-specific directories (`~/.claude/`, `~/.codex/`, `~/Library/Application Support/...`). An allowlist model must accommodate these.
- **Decision needed:** ADR-S3 documenting whether to implement, defer, or reject.
- **PR target:** ADR-S3 (document only, no code)

### Category C — Validate Before Fixing

These need proof-of-concept validation before implementation because the system has constraints the report did not account for.

#### C1: CSP Null in Tauri WebView (VULN-001)

- **Classification:** Defense-in-depth improvement requiring POC
- **CWE:** CWE-693 (Protection Mechanism Failure)
- **Location:** `src-tauri/tauri.conf.json:26` (`"csp": null`)
- **Ground-truth:** No CSP enforced on the WebView. React's default escaping mitigates most XSS.
- **Why POC first:** Tauri WebViews are not standard web applications. A CSP that breaks Vite dev mode, Tailwind CSS injection, Tauri IPC, or production asset loading would trade a marginal security gain for a broken UI. The report's recommended CSP string (`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self' ipc: http://ipc.localhost`) must be validated against:
  - Vite dev server (HMR, inline scripts)
  - Tailwind CSS (requires `'unsafe-inline'` for styles — confirmed in recommended string)
  - Tauri IPC (`ipc:` and `http://ipc.localhost` — included)
  - Production build (asset loading from `self`)
  - Any inline event handlers or data URIs
- **Approach:** ADR-S1 documents the investigation. A POC branch applies the CSP and runs `bun run dev` + `bun run build` + manual click-through of every view. If any view breaks, the CSP is tuned before merging.
- **PR target:** ADR-S1 + POC PR (S4)

### Category D — Governance / Dependency Maintenance

#### D1: AES-GCM 0.11 Upgrade (DEP-001)

- **Classification:** Dependency maintenance, NOT security
- **Location:** `src-tauri/Cargo.toml` (`aes-gcm = "0.10.3"`)
- **Ground-truth:** No CVE in 0.10.3. PR #35 (dependabot) is open but CI is FAILING. The upgrade to 0.11 is a routine version bump, not a security patch.
- **Why reclassified:** The report listed this as a P2 security finding. The Architecture Board correctly identified that "newer version exists" is not a security finding. This belongs in normal dependency maintenance.
- **Action:** Investigate PR #35 CI failure separately. If the CI failure is a compatibility issue, fix and merge. If it's a dependabot staleness issue, rebase. This is outside Program S scope.
- **PR target:** Investigate PR #35 separately (not Program S)

## 4. Plugin Engine Isolation Audit (Board Recommendation)

The Architecture Board recommended a dedicated audit of the plugin engine isolation boundary, identifying this as the highest-risk subsystem. This is tracked as a separate audit run.

**Audit scope (per board guidance):**
- QuickJS Runtime lifecycle
- Host API injection boundary
- Capability enforcement (deny-by-default)
- Serialization boundary (JS ↔ Rust)
- Native boundary (subprocess args)
- Plugin manifest validation
- QuickJS globals (prototype pollution, object freezing)
- Host object mutation (can plugins modify injected objects?)
- Timeout bypass (interrupt handler escape)
- Memory exhaustion (infinite recursion, large allocations)

**Status:** Scheduled as SEC-2026-07-09-B (separate run). Not blocking Category A fixes.
